# Memory Fix 14

发布标签：`2026.27-memoryfix-14`。产品源码提交：`41e63eeb756a0e6690631cf8be8c3cbce42973f7`。

本版从已发布的 Memory Fix 8 继续，保留其性能优化；不包含 Memory Fix 9、10 的实验修改。JAR 描述符版本仍为 `2026.27`。

## 自第 8 版以来的修复

| 修复 | 实际行为变化 |
| --- | --- |
| 第 11 版：Folia 越区受害者血量 | 避免在非所属区域读取实时血量。越区血量占位符明确返回 `unavailable`；当前 eco 数值转换回退为 0，同区继续返回实际血量。使用该占位符的公式需要了解此边界。 |
| 第 12 版：补种占位与种子扣除 | 延迟补种时再次检查目标为空且可以种植，确认成功条件后才扣种子，避免覆盖期间放入的潜影盒等方块。 |
| 第 13 版：非法种子材料 | 排除洞穴藤蔓方块，并在构造种子物品前检查材质确实可以作为物品，避免 `CAVE_VINES isn't an item`。 |
| 第 14 版：实际盾牌格挡 | 要求本次事件具有负的 `BLOCKING` 伤害修正。举盾但背面挨打不再触发格挡效果；正面全格挡、部分格挡仍可触发。 |

第 14 版保留原监听阶段、主体类型及取消/荆棘排除规则；`trigger_value` 仍使用原始事件伤害，没有改写效果数值、概率、配置冷却或新增全局冷却。没有增加缓存、任务或线程。

## 第 14 版验证

使用 Shiroha `26.2-DEV-398b90d` 的隔离服，绑定本机回环地址、新建测试世界，未操作生产服务器。

- 修改前：8 项新增回归测试中 4 项失败；原生攻击复现背面格挡修正为 0、受伤 4 HP，仍错误触发一次格挡效果。
- 修改后：完整构建成功，40 项自动测试全部通过，0 失败、0 错误、0 跳过。
- 17 组、117 次核心伤害检查通过，覆盖正面、背面、不举盾、副手、已取消、荆棘、吸收抵消、受控部分格挡及雷击/失明/挖掘疲劳/回血冷却。
- 连续 100 次成功格挡，对应 100 次实际事件、100 次效果回调。此项为两个测试玩家的受控串行测试，不是百人并发压测。
- 第 13→14 版 JAR 的 14,686 个条目没有增删，只有 `TriggerShieldBlock.class` 内容改变；此前修复及依赖字节相同。测试探针不在交付包中。
- [机器可读核验汇总](verified-results.json)记录原生对照、效果结果、测试统计、核心/依赖/JAR 散列及包体差异。
- [自动回归测试](../../core/common/src/test/kotlin/com/willfp/libreforge/triggers/impl/ShieldBlockTest.kt)和[修复源码](../../core/common/src/main/kotlin/com/willfp/libreforge/triggers/impl/TriggerShieldBlock.kt)随代码提交。

这不是一次新的整服性能提升测量，不给出 CPU 或内存下降百分比。仍未完成全部生产插件组合、投射物/爆炸、破盾与禁用的全部时序、热卸载、多个战斗区域和百人并发验收。部分格挡是对原生伤害事件的受控修正注入，不是自定义半格挡盾物品组件验收。保持原监听优先级，后续监听器再次改写事件的所有组合未验收。原生客户端存在部分粒子解析警告，结论依据核心事件及实际状态，不代表完整客户端视觉验收。

此前补种与越区修复本次通过原有自动测试和包体一致性确认保留，没有重新执行全部历史运行时场景。
